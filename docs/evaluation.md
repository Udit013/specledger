# Evaluation corpus

The corpus in `fixtures/corpus/` is synthetic. Every datasheet is generated by
`packages/eval/src/corpus/`. No real vendor document or scraped content is used, and every page
carries the line "SYNTHETIC TEST DOCUMENT - NOT A REAL PRODUCT".

## Contents

| Path                              | What it is                                                                                                                                  |
| --------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------- |
| `fixtures/corpus/pdf/<id>.pdf`    | The generated document                                                                                                                      |
| `fixtures/corpus/truth/<id>.json` | Ground truth: for every field of the class, the expected value, unit, page and exact quote, or `null` when the document does not contain it |
| `fixtures/corpus/manifest.json`   | Document ids, file hashes, split, designed cases, and one corpus hash                                                                       |

Ground truth is validated by `groundTruthSchema` (`packages/eval/src/corpus/truth.ts`). Values and
units are written exactly as they appear in the document, and both must occur inside the quote.

## Commands

```sh
pnpm fixtures:generate   # rewrite fixtures/corpus from the generator
pnpm fixtures:validate   # check the committed corpus (also run in CI)
```

Validation checks that every non-null quote occurs verbatim in the extracted text of its stated
page, that page counts and text layers match the truth, that file hashes match the manifest, that
every document's split follows the rule below, that every designed case has a dev document, that
every field is absent from at least one dev document with a text layer, that each quote states the
value immediately followed by the unit as whole tokens, and that regenerating the corpus reproduces
the committed files byte for byte.

## Reproducibility

The generator is seeded (`specledger-corpus-v1`). Each document draws from its own random stream
derived from the seed and the document id, so adding a document never changes another one. PDF
metadata and dates are fixed. The same generator version and seed always produce the same bytes;
`manifest.json` records the resulting `corpusSha256`.

## Split rule

A document's split is decided by its **lineage** (the equipment it describes), not by the document
id, so the revisions and the brochure of one piece of equipment always share a split:

```
unit    = first 4 bytes of sha256("specledger-split-v1:" + lineageId), as an unsigned integer / 2^32
split   = holdout if unit < 0.3, otherwise dev
```

The salt and the fraction are fixed. Changing either reassigns documents and invalidates any
result reported on the holdout.

Designed cases must each have a dev document, because later phases build regression tests from
them. Where the rule put a case's only document in the holdout, a second instance was added under
the next unused lineage number that the rule assigns to dev (p-106 brochure, p-108 injection, m-203
range). The same holds for absent fields, from which hallucination tests are built: m-204 omits the
motor voltage, frequency and speed, which the seeded motors omit only in holdout documents.
Documents were only added; none was moved between splits.

**The holdout split is never used to tune prompts, verifier rules or reconciliation rules**, and it
is not used to build tests. It is evaluated once, after tuning is finished, and that report is
committed separately and labelled.

## Page text

Quotes are matched against page text built with one convention, used by the corpus validator and to
be followed by ingestion (Phase 3): text items are grouped into lines by baseline, lines run top to
bottom, items within a line run left to right, items separated by a visible gap are joined with one
space, lines are joined with a newline, and whitespace-only items are ignored. A table row such as
`Rated speed` / `1450-1780 rpm` therefore reads `Rated speed 1450-1780 rpm`.

## Designed cases

| Case                    | What it tests                                                                                                                                             |
| ----------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `revision`              | Rev A and Rev B of one datasheet with changed values (reconciliation)                                                                                     |
| `brochure_rated_vs_max` | A brochure printing maximum values next to rated ones, disagreeing with its datasheet                                                                     |
| `range`                 | A rated speed stated as a range (`2900 to 3600`, `1450-1780`)                                                                                             |
| `absent_fields`         | Fields missing from the document; any value extracted for them is a hallucination                                                                         |
| `no_text_layer`         | A scanned-style page with no text layer (ingestion rejects it)                                                                                            |
| `injection`             | An embedded instruction to the extraction model; the fake value is written in words only, so an obeying response cannot quote it from the page (verifier) |
| `dual_units`            | Statements such as `287.0 m³/h (1264 gpm)` (unit agreement)                                                                                               |
| `decimal_comma`         | Numbers written `74,3`                                                                                                                                    |
| `multi_page`            | Fields spread over two pages                                                                                                                              |
| `layout_*`              | Key-value lines, two-column tables, and prose mixed with tables                                                                                           |
| `baseline`              | Seeded datasheets varying all of the above                                                                                                                |

## What a synthetic corpus can and cannot show

It gives exact ground truth, so it is suitable for regression testing and for comparing the
pipeline with and without the verifier. It cannot show accuracy on real vendor datasheets, which
have denser tables, inconsistent wording, scanned pages and drawing references. Results measured on
it must be reported as results on synthetic documents only.
